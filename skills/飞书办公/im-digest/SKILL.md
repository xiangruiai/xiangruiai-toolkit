# 小时情报 · 微信 + 飞书行动摘要

把用户自己的微信和飞书，按时间窗收成一份能动手的盘点：先写今天还得处理的事，再写客户卡点、值得知道的信息、可写的选题和已经解决的事。默认一天多档，而不是一天结束才复盘。

本 skill 只提供通用步骤、脚本和版式。账号、知识空间、重点会话、机器位置和日程属于用户本地配置或定时 routine，不要写进 skill 正文，也不要写进共享记忆。

## 1. 何时使用，何时不用

使用：

- 用户说小时情报、盘点一下、这几个小时有什么要处理的、把微信和飞书收一收
- 已约定在 09:00、13:00、18:00 或类似节点自动跑一档
- 需要同时看微信本地记录和飞书（私聊、@、邮件、日历、文档、任务）

不要用它来：

- 给某个微信群做杂志风日报（那是群日报类 skill）
- 写给上级看的飞书全日复盘文档（那是收工日志类 skill）
- 代用户回复消息、改别人的文档、或给群发卡片

## 2. 前置条件

- 微信桌面版在**用户自己的电脑**上保持开着并已登录。vchat 必须跑在这台机器上，不能只在没有微信客户端的远程环境里猜数据
- 已安装同一工具箱里的 [vchat](https://github.com/xiangruiai/xiangruiai-toolkit/tree/main/cli/vchat)（本仓库 `cli/vchat`，建议 2.1.0+），`vchat doctor` 正常。需要刷新本地库时先 `vchat decrypt`
- 已安装官方 [lark-cli](https://github.com/larksuite/cli)（`npx @larksuite/cli@latest install`），已完成 `config init` 和 `auth login`，`lark-cli auth status` 或 `lark-cli doctor` 可用
- 跑命令前 `export TZ=Asia/Shanghai`（或配置里的时区）。时间参数带时区，如 `+08:00`
- 本地已有一份配置（参见 `examples/config.example.yaml`）：自己的姓名、可选 open_id、知识空间和父节点、重点会话列表、状态目录。这些不要提交到 git，也不要写回本 skill

## 3. Skill、配置和 routine 怎么分工

| 放这里 | 放用户本地配置 / routine |
|---|---|
| 扫描、去重、五块结构、卡片和日节点版式、只读边界、隐私规则 | 运行时刻表、时区、机器位置 |
| 通用命令、脚本、状态字段含义、建议的条目惯例 | 知识空间、日节点父节点、Page 链接 |
| | 自己的姓名、open_id、重点会话、跳过的机器人和客服会话、客户别名 |
| | 条目上限、收起规则是否启用，以及安静档是否发卡片 |

定时触发时，routine 只需写：到点后按本 skill 跑一档，配置文件在何处，必要时机器离线则延期补扫。不要把客户名单或聊天原文写进 routine。

## 4. 只读边界和隐私

- 默认只读。不要用微信或飞书替用户发消息、回复、转发，不要 `calendar +rsvp`，不要改他人文档，不要审批或改任务
- 唯一默认写操作：用机器人身份把卡片发给**当前登录用户本人**；以及更新用户自己知识空间里专门用于小时情报的日节点。卡片不要发到群或别人
- 验证码、兑换码、卡号、密钥、完整聊天原文不要写入状态文件、Page、卡片、日节点、skill 或记忆。状态里只留短句、来源和必要链接
- 原始扫描文件（`wd_*.txt`、飞书 JSON）只放本地数据目录，不要提交，也不要长期贴进对话
- 只处理用户自己账号、自己有合法访问权的数据

## 5. 时间窗和状态文件

每天一份状态文件：`{state_dir}/{YYYY-MM-DD}.json`，字段见 `references/state-schema.md`。它是当天唯一事实来源。

1. 读今天的状态文件；没有就按 `examples/state.example.json` 建空骨架
2. 本档起点优先用 `last_scan_until`（微信、飞书、朋友圈可分开）。当天第一档若没有上次时间，从当天 00:00 开始
3. 本档终点是现在。上一档机器离线时，把起点改成上次成功扫描的时间，一次补扫，并在 `coverage_log` 写明
4. 跑完后更新 `last_scan_until`、`coverage`、`last_run`。扫描失败的源记进 `skipped`，不要假装扫过

## 6. 全量扫描和去重

先采集，后判断。命令细节见 `references/wechat-scan.md` 和 `references/feishu-recipes.md`。

微信（在已登录的那台电脑上）：

1. 需要时 `vchat decrypt`，再 `vchat doctor`
2. `python3 scripts/scan_wechat.py --since "$SINCE" -o "$RAW/wd_MMDD_HHMM.txt"`
3. 按需补：`vchat --json sns-ls -n 150`、`sns-mentions`、`biz-ls`。朋友圈评论往往没有正文；隔夜后朋友圈可能还停在前一晚
4. 查窗口内是否有人 @ 用户或点名时，优先在扫描摘要里检索。`vchat search` 不按时间排序

飞书（一律 `--as user`）：

1. `bash scripts/scan_feishu.sh`，或按手册跑 @我、私聊、群消息、本人发出的承诺、邮件、日历、任务、审批、近几日文档
2. 重点会话再用 `im +chat-messages-list` 补拉（搜索会漏刚发的消息）
3. 群消息若 `has_more=true`，把 `--end` 设成第一段最早时间再补一段
4. 验证码邮件跳过。单据类通知可合并成一条值得知道的。日历只读，待回复邀请要报，但不要代为回复

去重和归类：

- 同一件事出现在微信和飞书，合并为一条，`source` 写成 `微信+飞书`，保留两边链接
- 同一人多件小事合并成一条短句
- 已在客户与商单里、这轮只是在等对方的，不要再在要处理的里重复一行
- 用 `new` / `changed` / `carried` 标记本档变化，供安静档判断
- 会话显示名若带【】前缀，写入状态前改成 `前缀 · 其余`
- 链接标签写成 `类型：文案`。全文不要使用直角引号

## 7. 建议的条目惯例（可配置，不是死规则）

这些是经过实际使用后的推荐默认值，用户可以改，但改了要写进自己的配置或状态里的 `todo_rule`。

- 要处理的只放今天用户还得动手的，或近几日有截止日期的，尽量不超过约 12 条
- 已在客户与商单、且这轮在等对方的，不重复进要处理的
- 低优先级、超过约 3 天没有新进展的欠回复，收入 `todo_parked`，不要标成已解决或已撤下
- 傍晚档（默认 18:00）用一行汇总收起的条数；有新消息或截止日期临近再抬回要处理的
- 最要紧写一句真正最急的；不要把客户进展复述两遍
- 截止日期临近、账号安全待确认、需要用户本人回复的，优先进入要处理的

## 8. 五个板块

写状态文件时用短句，不要贴聊天记录。

1. **最要紧**：一句话
2. **要处理的**：优先级（高 / 中 / 低）、事项、来源 · 会话 · 时间、必要链接
3. **客户与商单**：客户、项目、阶段、下一步（卡点）、来源。别名可用本地 `client_aliases.json` 合并
4. **值得知道的**：需要知道但不必马上动手的信息
5. **可写的选题**：从讨论里抽出可写成内容的角度（没有就留空）
6. **今日已解决**：今天已经完成的，不要再留在要处理的里

客户阶段常用：执行中、交付、等确认、等回款、询价等。金额、卡号、验证码不要写进来。

## 9. 更新 Page（可选）

若用户使用 Cursor / Grok Page，并且配置打开了这项：

1. `python3 scripts/mkpage.py --state data/YYYY-MM-DD.json -o page-MMDD.tsx`
2. 和当前 Page 源码对比，只改变化的行；空列表必须是 `rows={[]}`
3. 呈现规则见 `references/page-style.md`。不要套用飞书卡片的 200 元素回退

没有 Page 工具就跳过，不影响卡片和日节点。

## 10. 生成并发送飞书卡片

```bash
python3 scripts/gen_card.py --state data/YYYY-MM-DD.json \
  --aliases config/client_aliases.json \
  -o daily-YYYY-MM-DD.json
# 若这档没有新增或变化，且配置了 quiet_if_no_change，跳过发送，只保留状态
bash scripts/send_card.sh daily-YYYY-MM-DD.json
```

卡片只发给 `lark-cli auth status` 里的当前用户。生成脚本会过滤已解决的待办，并在元素超过 200 时自动降级版式，但不删内容。版式说明见 `references/feishu-recipes.md`。

## 11. 同步知识库日节点（可选）

若配置了知识空间和父节点：

1. 查当月节点，没有就先建月份节点
2. 当天没有日节点则创建，标题默认 `{date} 小时情报`
3. 已有则用 `scripts/mkday_md.py` 生成 Markdown，`docs +update --command overwrite` 覆盖
4. 再按手册把 `[高] ` / `[中] ` / `[低] ` 替换成彩色标签。某一级没有条目时替换失败是正常的

只改用户自己的归档节点。命令见 `references/feishu-recipes.md`。

## 12. 建议的日程和安静档

建议每天 09:00、13:00、18:00 各一档；用户可以改。某档机器离线，下一档连通后按 `last_scan_until` 补扫。

若配置了 `quiet_if_no_change`，且本档没有新增或变化的条目、也没有覆盖缺口，就不要再发一张重复卡片。仍要更新扫描截止时间，并在需要时给用户一句很短的说明。

跑完后向用户交付：最要紧的一句话、要处理的清单（或指出没有变化）、Page / 日节点 / 卡片是否已更新。不要把原始聊天粘回去。
